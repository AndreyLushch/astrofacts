# astrofacts

Расчётный слой астрологических данных: HTTP-сервис, который по дате и таймзоне отдаёт
астрономические факты суток — события с моментами времени, а не снимок неба на полночь.

Сервис слушает `127.0.0.1`, аутентификации нет, наружу не выставляется. В сеть не ходит.

## Лицензия и граница с потребителями

AGPL-3.0, см. `LICENSE`. Сервис использует Swiss Ephemeris (Astrodienst AG) на условиях AGPL,
см. `NOTICE`. Потребители обращаются к сервису только по HTTP и JSON: код astrofacts ими
не импортируется, клиентской библиотеки нет и появляться не должно. Контракт — JSON Schema
в `/openapi.json` и номер версии схемы в теле ответа.

## API

    GET /day?date=2026-10-23&tz=Europe/Moscow[&lookahead=6][&schema=1]
    GET /health

- `date` — локальная дата, `tz` — таймзона IANA. Сутки — полуоткрытый интервал от локальной
  полуночи до следующей; в `meta.day_length_hours` его длина (23, 24 или 25 при переводе часов).
- `lookahead` — окно опережения в часах после конца суток (по умолчанию и предел — в конфигурации).
  События из окна отдаются с `beyond_day: true`.
- `schema` — версия схемы, которую ожидает потребитель. При несовпадении — ответ 409
  `{"error": "schema_version_mismatch", "supported_schema_versions": [...]}`. Потребителю стоит
  передавать этот параметр всегда: рассинхрон версий тогда виден сразу, а не при разборе JSON.
- Ошибки запроса — 422 с телом `{"error": код, "detail": текст}`.

Ответ `DayFacts`: общая часть (Луна, точные аспекты, ингрессии, станции, лунации и затмения,
фон) и проекция на каждый из 12 знаков (солярные дома, управитель, события суток `today`).
Ответ за дату детерминирован и кешируется в памяти процесса по ключу
(дата, таймзона, окно опережения, хэш конфигурации).

Чего в ответе нет намеренно: абсолютных долгот и аспектов вне орба.

### Как читать ответ

- **Время** — в таймзоне запроса, с точностью до минуты; секунды отбрасываются, а не округляются.
- **Аспекты** отбираются по событию: в ответ попадает аспект, ставший точным в эти сутки.
  Орб к ним не применяется. Аспекты Луны лежат в `moon.aspects`, остальные — в `exact_aspects`.
- **Время или дата.** Если взаимная скорость пары в момент точности ниже порога
  (`speed.slow_threshold_deg_per_day`), аспект отдаётся датой без времени. Ингрессии и станции
  отдаются с временем всегда.
- **Фон** (`background.slow_aspects`) — аспекты между медленными планетами в пределах орба
  из `orbs.background`, с состоянием `applying` / `exact` / `separating`.
- **Фаза Луны.** Главная фаза (новолуние, первая четверть, полнолуние, последняя четверть)
  называется только в сутки её точного момента, в остальные дни — промежуточная.
- **Затмения** — глобальные (где-либо на Земле), без видимости из конкретного места.
- **`signs[знак].today`** — те же события суток, разложенные по домам знака; `involves_ruler`
  отмечает события с участием управителя. Станции из окна на несколько дней вперёд сюда
  не попадают: они есть только в общем списке `stations` с `days_ahead`.

### Луна без курса

Интервал от последнего точного аспекта Луны в знаке до её входа в следующий знак.
Конвенций две, и они дают разное начало интервала:

- **современная** — считаются аспекты к Солнцу, Меркурию, Венере, Марсу, Юпитеру, Сатурну,
  Урану, Нептуну и Плутону. **Включена по умолчанию**; сверена вручную с astro-seek.com;
- **традиционная** — только к семи классическим телам, от Солнца до Сатурна. Включается
  списком `void_of_course.bodies` в конфигурации.

В обеих учитываются пять мажорных аспектов (`void_of_course.aspects`).

Наше решение, а не конвенция: если за всё пребывание в знаке Луна не делает ни одного
учитываемого аспекта, интервал начинается с её входа в знак, а `last_aspect` равен `null`.
С внешними источниками этот случай не сверялся.

## Файлы эфемерид

Сервису нужны два файла Swiss Ephemeris: `sepl_18.se1` (планеты) и `semo_18.se1` (Луна),
годы 1800–2399. **В репозитории и дистрибутиве их нет** — они загружаются при развёртывании:

    python tools/fetch_ephemeris.py [каталог]

- **Откуда:** официальный репозиторий Astrodienst, https://github.com/aloistr/swisseph,
  каталог `ephe/`, зафиксированный коммит; контрольные суммы проверяются.
- **На каких условиях:** Swiss Ephemeris распространяется по двойной лицензии — AGPL либо
  платная Swiss Ephemeris Professional License. Этот проект использует её на условиях AGPL.
- **Почему не в репозитории:** отдельного текста лицензии именно на файлы данных у Astrodienst
  нет. Чтобы не распространять их на основании вывода, а не явного разрешения, проект
  их не распространяет вовсе: каждый получает файлы у правообладателя.

Каталог задаётся переменной `ASTROFACTS_EPHE_DIR` (по умолчанию `src/astrofacts/data/ephe`).
При старте сервис проверяет наличие и контрольные суммы файлов и без них не запускается;
сам он ничего не скачивает. Развёртывание требует сети, работа сервиса — нет.

## Запуск

    python -m astrofacts

| Переменная | По умолчанию | |
|---|---|---|
| `ASTROFACTS_HOST` | `127.0.0.1` | адрес |
| `ASTROFACTS_PORT` | `8765` | порт |
| `ASTROFACTS_EPHE_DIR` | каталог в пакете | файлы эфемерид |
| `ASTROFACTS_CONFIG` | встроенный файл | конфигурация расчёта |

Шаблон unit-файла — `deploy/astrofacts.service`.

## Конфигурация расчёта

`src/astrofacts/data/default.toml`: тела, аспекты, орбы фона, порог скорости, конвенция Луны
без курса, окно станций, окно опережения, схема управителей (`modern` / `traditional`), размер
кеша. Хэш действующей конфигурации отдаётся в `meta.config_hash` и в `/health`: по нему видно,
с какими орбами и правилами посчитан конкретный ответ.

## Устройство

Расчёт идёт в два шага.

1. `sky.scan_day` сканирует сутки и строит `DaySky` — траектории тел и события с точными
   моментами. Дорогой шаг, выполняется один раз на дату.
2. `assemble.build_day_facts` проецирует `DaySky` на системы отсчёта (`frames`). Сейчас система
   одна — знак как первый дом (`SolarSignFrame`). Натальная карта станет второй реализацией
   того же интерфейса без изменения первого шага.

Все обращения к Swiss Ephemeris — в модуле `ephemeris`; остальной код работает со своими типами.

## Разработка

    python3 -m venv .venv
    .venv/bin/pip install --find-links ~/wheels -e '.[test]'
    .venv/bin/python tools/fetch_ephemeris.py          # файлы эфемерид
    .venv/bin/python tools/fetch_reference_kernel.py   # ядро JPL для сверочных тестов
    .venv/bin/python -m pytest

Готового колеса pyswisseph под Python 3.12 на PyPI нет: оно либо собирается из исходников
(нужны компилятор и `python3-dev`), либо берётся собранным через `--find-links`.

Тесты работают без сети. Положения тел и моменты событий сверяются с независимой реализацией —
astropy/ERFA по ядру JPL DE432s (`tests/data/`, в git не хранится). Без ядра эти тесты
пропускаются с сообщением; без файлов эфемерид тесты не запускаются вовсе.

Вспомогательные скрипты: `tools/precision_stats.py` — сколько событий отдаётся с временем
и сколько датой; `tools/voc_dates.py` — интервалы Луны без курса по обеим конвенциям.
